# ED-R002：Early Decision-only Twilight attention 与近邻核查

日期：2026-10-22；轮次类型：代码实现、CPU组件实验及文献核查。前序：[ED-R001 固定版本](https://github.com/wangzhengyu2017/Twilight/blob/f69ec467ce5a81e26b1e828a2a040839c389ac7f/early%20decision/README.md)。本文件与本轮代码、协议及结果在同一提交归档，完整变化可按本路径的首次提交与基线 `f69ec46` 比较。

## 1. 当时的 idea 与目标

用户要求从 W 与 X 在完整 QK 前生成 B0，并将该思路实际接入 Twilight；启用此路径时舍去 DS selector 和 Twilight Top-p，仅用选中 KV 执行正式 attention。同步派出两个子 agent，分别核查近年文献和实现／实验；最终审核与收尾由主 agent 完成。

## 3. 结果支持与未验证项

固定FP/rank4/k32时，有利谱no-RoPE输出cos约0.9994、relative L2约0.0670、retained mass约0.9435；logits Top-k recall约0.9766，而token cos(q,k) oracle recall约0.6406。加位置旋转但仍pre-RoPE预测时，输出cos降至约0.6550、mass约0.4162。两种oracle与最终输出不可互相替代。

该固定预算warm MAC约为dense QK＋AV的0.311；但初始metadata构建只摊4步时升至2.291，QR/SVD时间另列。CPU RESULT约0.20–0.31ms，dense约0.020–0.025ms，没有实测加速。保守界在有利谱也平均保留236.25个token，平坦谱几乎全保留；召回保证并不等于高效。

576步结果经主agent独立审计：192个全保留step allclose，144个no-RoPE保守step的requested-k recall为1。24项测试通过。新增压缩往返测试初次因系统临时目录写权限失败，改用已校验的工作区临时目录后通过；这不改变attention算法或已记录数值。

文献确认CLOVER／A³、Palu、Franco等覆盖联合权重分解或离线融合，LoRA-Sparse／SALS／InfiniGen等支持提前proxy筛选。因此联合SVD和“完整QK前预测”不能单独主张创新；残差筛选与真实系统收益仍需额外证据。

未执行完整checkpoint、真实安装版Transformers集成、PPL、GPU／硬件性能；stub与合成组件不替代它们。RoPE heuristic不继承原区间保证。

## 4. 为什么修改 idea

| 发现 | 修改原因 | 下一轮形成的方案 | 证据继承边界 |
| --- | --- | --- | --- |
| 直接数学先例存在 | 不能把联合权重分解本身当贡献 | 研究位置感知筛选、界的紧致性和投影复用 | 文献事实可继承，未发现同组合不等于证明新颖 |
| RoPE预测质量下降 | 固定A无法统一真实相对旋转 | 先处理位置，再用真实trace评估B0 | no-RoPE推导不能作为RoPE保证 |
| 保守界保留大多数KV | 高召回本身不足以省工作 | 比较更紧的界／分块／路由与经验预算 | 保留本轮失败结果；替代机制需新结果 |
| warm MAC少但CPU慢，短摊销昂贵 | 低维扫描、复制与初始化不能忽略 | 预分配cache、GQA复用、较长decode摊销、设备kernel | 逻辑账本可继承，速度需重新实测 |
