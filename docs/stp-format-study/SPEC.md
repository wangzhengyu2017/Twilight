## 3. Diagnose existing TC information loss first

For TC b=4 total bits, r=4 and H_TC(x)=16 floor(x/16). Compute in signed int16/int32; never right-shift unsigned bytes or truncate division toward zero. Residual l=x-H_TC(x) lies in [0,15]. Thus -1→-16, +1→0, -15→-16, +15→0, -16→-16, +16→16, -127→-128, +127→112. Reconstructed -128 is legal even though source quantization excludes it.

This is a mathematical asymmetric reconstruction, not proof of catastrophic attention error. A nonzero negative prefix does not itself mean preserved magnitude information: all -1..-16 share one prefix. For q=Q_hat+eQ, k=K_hat+eK,
`q·k - Q_hat·K_hat = Q_hat·eK + eQ·K_hat + eQ·eK`.
Both cross terms matter. Original real scales and 1/sqrt(D) must multiply the reconstruction before softmax; even a uniform logit multiplier changes Top-p mass.

Before any format full run, use actual captured source Q8/K8 to measure by layer/head/stage: source-code histogram and sign balance; prefix histogram, unique occupancy, zeros/nonzeros, collisions and conditional residual variance; signed mean error/MAE/MSE, separately for positive/negative/zero values; QK logit MAE/MSE/bias, rank/tie and saturation statistics; reference mass retained, missing-mass shortfall, recall/precision/Jaccard and selected count. Prefix occupancy or entropy alone cannot establish predictor usefulness. Preserve all failures and sign-stratified statistics. This diagnosis is read-only on copied artifacts and must not perturb the running experiment.

## 4. Concrete format definitions and byte budgets

### 4.1 TC control

One source int8 byte; predictor takes four physical high bits including sign. Logical signed nibble h=floor(x/16)∈[-8,7], reconstruct xhat=16h. Original scale remains unchanged. Preserve the existing production operation order: compute the signed integer-prefix dot `dot=sum(hQ*hK)` using the existing validated FP32 integer-exact path, then `logits=(((dot*(aQ*aK))*sQ)*sK)/sqrt(D)`, where aQ=2^(8-bQ), aK=2^(8-bK). The frozen local backend line147 uses this ordered expression. The factor is256 for Q4K4 and16 for Q8K4. Do not refactor reused TC controls into DQ-first matmul: FP32 rounding/order is part of their contract.

### 4.2 SM8 → SM4 (ready to specify)

Encode source integer x in uint8 as `u=(x<0 ? 128 : 0) | abs(int16(x))`. Decode `(-1)^sign * (u&127)`. Normalize zero to positive zero. Negative zero is not emitted. This losslessly recodes every x∈[-127,127]; it does not quantize the source again.

Four bits TOTAL means one sign plus three high magnitude bits: `m3=abs(x)//16`, `sign=(x<0)`, `xhatSM=sign_multiplier*16*m3`. It corresponds to physical byte bits7..4, magnitude low four bits discarded. Examples ±1→0, ±15→0, ±16→±16, ±127→±112. Canonicalize reconstructed zero before statistics. Preserve the original scale s. For production, use signed magnitude-prefix integers `g_b(x)=sign_multiplier*floor(abs(x)/2^(8-b))`, with g8=x. Compute `dot=sum(g_bQ(q)*g_bK(k))` and apply exactly the existing ordered expression `(((dot*(aQ*aK))*sQ)*sK)/sqrt(D)`. Q4K4 uses factor256; Q8K4 uses factor16. This matches the TC operation structure while changing only prefix reconstruction. Real operand values `a*g*s` are saved/derived for interpretation, not used to silently switch the production reduction to DQ-first. Any different arithmetic path must be separately named and validated on the same inputs before replacing this contract.

Four magnitude bits PLUS sign would instead retain five bits total (`abs(x)//8`, reconstruct multiples of8). It is a separately named optional 5-bit ablation, never called Q4×K4 or mixed into the main18 cells. Physical prototype tensors may use byte storage; report logical retained bits separately from actual bytes and conversion cost.

### 4.3 MX ambiguity and recommended default

“MX” is a family. Recommended strict MSB interpretation: **MXINT8-TC4 predictor sidecar**, called `mxint8_tc4_sidecar`. It is not lossless recoding, and it still has TC negative-floor behavior. Its intervention adds block normalization, rounding/clamping and shared-scale information. It cannot isolate bit representation alone. This limitation must appear next to its results.

Construct sidecar input exclusively from original DQ values `v_d=float32(x_d)*float32(s)` so every variant starts from the same quantized source, not original floating Q/K. For each token/head, divide the head dimension into contiguous blocks32; D128 gives four blocks and no tail. Do not group across heads, tokens or Q/K. General tails use zero padding and an explicit valid-D mask, never extra dot terms.

For nonzero block maximum A=max|v|, let e=floor(log2(A)), X=2^e, E8M0 byte=e+127. This is the §6.3 algorithm for MXINT8 because its largest representable power of two is1. For zero block choose E8M0=127 (X=1), all codes0, a frozen study convention. Require finite representable scales; fail instead of silently clipping exponent. Convert `c=clamp(RNE(64*v/X),-127,127)` in a sufficiently wide type, store int8. Freeze ties-to-even and symmetric saturation; count clamps, zero blocks and underflow. Full sidecar reconstruction is `vMX=X*c/64`.

Take logical TC high4 `h=floor(c/16)`, reconstruct predictor real values `vhatMX=X*(16*h)/64=X*h/4`. For query/key position j, block b:
`Lhat_j=(1/sqrt(D))*sum_b[(XQ_b*XK_jb/16)*sum_{d in b}(hQ_d*hK_jd)]`.
Implement FP32 DQ-first dot for this MX sidecar only; TC and SM retain their ordered integer-dot-then-scale path above; the block-factor formula is an independent mathematical oracle with separately stated rounding tolerance. Do not multiply original sQ/sK again: they were already used when forming v. E8M0 scale is per block and mandatory in the predictor, not a single post-dot scale.

Payload: full sidecar 32×8+8=264 bits/block (8.25/element); retained high4 sidecar 32×4+8=136 bits/block (4.25/element). D128: 128 code bytes +4 scale bytes full; 64 packed prefix bytes+4 scale bytes predictor. Prototype uncompressed h may occupy128 bytes; report that actual allocation. Original full codes/scales retained for final execution add further storage. Never advertise this as a metadata-free 4-bit comparison.

Deferred alternative, **not in the initial matrix**: **MXFP4 E2M1 sidecar**. The user chose MXINT8 first and would consider MXFP4 only if those results are unsatisfactory. For each DQ block A>0 choose X=2^(floor(log2(A))-2), quantize v/X to nearest-even member of `{0,±.5,±1,±1.5,±2,±3,±4,±6}`, sign-preserving saturation at6; zero-block convention as above. Element encoding is sign1/exponent2/mantissa1, bias1. It is a true native4 element with4.25 bits/element including shared scale, but is NOT “high4 of Q8/K8” and must have a separate variant_id/design label. Do not silently treat the upper4 bits of FP8 as E2M1. This alternative must not be scheduled initially; its six-cell follow-up is authorized only if the predeclared decision below activates it.

For Q8×K4, decode Q at its full8 predictor precision and K at prefix4. SM8 full-Q decoding is exactly the original source integer times original scale. RS full-Q must prove the same identity after its source gate. MX full-Q uses `XQ*cQ/64`, while K uses `XK*hK/4`; its block dot coefficient is `XQ*XK/256` multiplying `sum(cQ*hK)`. Original source scales must not be multiplied again. This MX Q8 predictor is full sidecar8, not original Q8; record the distinction. An original-Q8 × MX-K4 hybrid would be a separately proposed ablation, not this format-consistent main cell.

### MXINT8 endpoint profile

This study explicitly selects `endpoint_policy=symmetric_omit_min_negative`, codes [-127,127], for the predictor-only MXINT8 sidecar. OCP MX v1.0 §5.3.4 (printed p13) permits leaving the most-negative value unused for symmetry; Table6 (p14) lists symmetric extrema. This is a permitted profile, not a claim that signed8 lacks the -128 code. Include the -127.5 RNE/clamp boundary in independent codec tests. Changing to the optional asymmetric endpoint profile is a separate design change, not a repair to the current contract. See `../review/mx-endpoint-primary-source-correction.md` for primary-source evidence.

### Implemented bounded binary scaling

PyTorch FP32 `ldexp(value, shift)` can overflow its intermediate power-of-two factor for legal MX exponent extremes even when the desired result is finite. The implementation splits each binary shift into two bounded shifts whose factors are representable. The first scaling of a nonzero MXINT8 integer or E2M1 reconstruction remains normal; only the final step may round to a subnormal. Encoding normalizes the finite input before RNE. This preserves the declared formula rather than clipping the scale range. Independent byte-exact tests cover every finite E8M0 power boundary and its adjacent FP32 values, including the originally failing exponents -127 through -122; CPU and CUDA pass. Failure evidence is retained under preparation/acceptance.
